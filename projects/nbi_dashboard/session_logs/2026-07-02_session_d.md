## Bug fixed: test-suite pool poisoning (regression from hierarchy merge)

**Symptom:** 314 unit tests / 44 files failing with "Cannot use a pool after calling end on the pool" in truncate() beforeEach. NOT the stale-fixture issue the handoff predicted.

**Root cause (systematic-debugging, reproduced minimally):** `tests/unit/retype.test.mjs:10` (written during the hierarchy feature) called `afterAll(() => end())` on the pool from `tests/helpers/db.js`. That helper is CJS loaded via createRequire, so Node's require cache shares ONE pool instance across all test files in vitest's single fork (`singleFork: true`). retype's afterAll closed the pool for every file that ran after it (44 files). Sibling files escape.test.mjs:24 and helpers.test.mjs:22 explicitly document the "No afterAll(end())" convention; retype.test.mjs violated it.

**Fix:**
- `tests/unit/retype.test.mjs` -- removed the `end` import and `afterAll(end())`, added the convention comment.
- `tests/helpers/db.js` -- deleted the idempotent `end()` helper entirely (it was a symptom-fix for double-end throws and imported nowhere else; Playwright global-setup only imports truncate). Documented the pool lifecycle contract: never end from a test file; pool dies with the fork.

**Evidence:** reproduction pair (retype + task-access) failed 4 tests before fix, 15/15 green after. Full unit suite re-run in progress.

**Handoff correction:** the "stale test-DB baseline fixture" theory in docs/HANDOFF.md was wrong or already resolved by commit 046530d -- global-setup completed fine and there were no FK errors in the run. The failures were entirely the pool kill. Will confirm from the clean full-suite run.
