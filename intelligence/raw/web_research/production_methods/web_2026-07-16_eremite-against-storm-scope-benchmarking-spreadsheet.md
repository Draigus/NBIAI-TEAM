# Eremite Games / Against the Storm -- Comparative Scope Management via Market Benchmarking

## Key Content (max 200 words)

Eremite Games (small Polish studio, first large-scale game) managed scope for Against the Storm using a structured market analysis approach rather than internal estimation alone. The team built a spreadsheet cataloguing comparable citybuilder studios across budget, team size, and feature set -- ranging from Colossal Order (Cities: Skylines, large studio) down to Toukana Interactive (Dorfromantik, comparable indie scale). The humbling conclusion: "There's no trick we can pull off, and no 'main character' advantage we have."

The practical anchor was benchmarking against Lion Shield LLC's Kingdoms and Castles -- a studio of similar size and ambition -- rather than aspirational large-studio comparisons. This gave a realistic reference for development timeline and feature scope.

Feature prioritisation used a single criterion: "if a feature could add value to the game experience in the least amount of time to implement it." Anything failing this test was deferred. Budget proposals included a non-negotiable 25% safety buffer. Lead designer Ogłoziński: "Every hastily written line of code and patchwork solution you do today is extra work you have to do tomorrow."

A public demo secured via Steam event placement served as the first external milestone gate, providing real player feedback before committing to full production scope.

## Decisions / Insights

- Benchmarking scope against studios of genuinely comparable size (not aspirational targets) produces realistic timelines -- the comparison must be calibrated to budget and headcount, not genre ambition
- A comparative market spreadsheet (budget, team, feature set, monetisation) is a pre-production tool, not just business development; it sets the expectation floor and prevents "we should have X because [big studio] has X" creep
- The single feature prioritisation criterion -- value to experience vs time to implement -- is simple enough to apply consistently across disciplines without committee decisions
- A 25% safety buffer is non-negotiable in Eremite's model; the lead designer frames technical debt as future development cost, not future option
- A public demo placed in a high-traffic platform event (Steam Next Fest equivalent) functions as a low-cost external milestone gate: it forces production-quality playability at a defined date and generates real feedback before internal estimates harden

## Context

Primary source: Game Developer (gamedeveloper.com) article reporting on Eremite Games lead designer Jakub Ogłoziński discussing scope management. Against the Storm shipped from Early Access to 1.0 in 2023 after a multi-year development as a solo-founder-to-small-team project. The game became one of the highest-rated city builders of 2023 on Steam. The team was self-described as resource-constrained with no prior shipped game at this scale. ## Applicability

Directly applicable when NBI clients are setting scope for a first project at a new scale -- particularly studios transitioning from small-team prototypes to a full production cycle with investor or publisher involvement. The benchmarking spreadsheet approach translates directly to client workshops: build the comparison grid before writing the first milestone plan. The value/time prioritisation criterion is usable as a standing backlog rule. The public demo as milestone gate is especially relevant for studios planning Early Access or publisher pitches -- it externalises a gate that would otherwise be set arbitrarily internally.
