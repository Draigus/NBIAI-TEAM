# Rob Sandberg (Production Alchemist) -- Scrum Zombies: Kanban and Flow-Based Production for Game Studios

## Key Content (max 200 words)

Sandberg argues that game studios -- particularly live service teams -- use Scrum as process theatre rather than because it fits their actual work patterns. He identifies five specific failure modes when Scrum is applied to games: (1) design mismatch -- Scrum was built for product discovery with unknown outcomes, not maintaining running games with content pipelines and patch stability; (2) artificial delivery cycles -- features span weeks or months with external blockers, making sprint demos of incomplete fragments meaningless; (3) Parkinson expansion -- small tasks fill sprint duration despite being completable in hours; (4) hollow metrics -- story points optimise for timeboxes, not player impact, and "done" becomes "done from engineering's side"; (5) ceremony overload -- the same retro topics (carryover, scope creep) repeat without addressing root causes.

Proposed alternative: pull-based Kanban with WIP limits, cycle time measurement, and work moving based on readiness rather than calendar. Hybrid model for most studios: Scrum-like sprints for active development, Kanban for live ops and support streams.

A second failure mode Sandberg addresses: treating frozen GDDs as fixed specifications while claiming Agile practice is "structurally waterfall." Teams updating backlogs from playtesting are Agile; teams defending design documents against new information are not.

## Decisions / Insights

- "Agile isn't a set of rules. It's a mindset" -- studios can abandon Scrum ceremonies that create friction while retaining planning feedback loops.
- Match process rhythm to actual release cadence: if shipping is weekly, anchor planning to Thursday; if events reset monthly, align cycles to that reality.
- Replace velocity with lead time and cycle time as primary throughput metrics -- these correlate with player-facing delivery where story points do not.
- The GDD anti-pattern is a clear diagnostic: if the team is defending the design document against playtesting data, it is running waterfall with a Scrum vocabulary.
- "You can learn Jira in a week. The rest takes years" -- the process switch is fast; the cultural shift to reading actual work patterns is the real change.
