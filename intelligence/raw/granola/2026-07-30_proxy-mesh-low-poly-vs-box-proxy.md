# Proxy Mesh Standard: Low-Poly Over Box Proxy for Simple Character Types

## Key Content

Production standard decision on proxy mesh approach at a ~60-person MMO studio:

**The request:** Animation team requested a box-proxy version of an approved low-poly mesh for a character with no bending joints (a hovering, separated-arm character). Request was escalated by a department head in a leads meeting, accompanied by YouTube tutorial videos shown to the art lead to explain box proxies.

**The art lead's decision:** Declined. The low-poly model is already the simplest usable proxy for this character type. A character with no bending joints (no knees, no elbows flexing) is inherently simpler to animate than a biped. The low-poly mesh already provides the deformation approximation an animator needs.

**CPO's read:** Adapting the production pipeline and asset standards to accommodate junior skill gaps is the wrong direction. The animation team should build competency with industry-standard low-poly proxies, not receive simplified assets that reduce the skill ceiling. Box proxies were needed only in older pipelines or for extremely high-density characters.

**How the request reached the leads meeting:** A junior request was escalated by a department head to the art lead in front of all art leads, with supporting materials. The art lead assessed it on merit and declined publicly, which is appropriate.

## Decisions / Insights

- Studio art lead decided: low-poly proxy is sufficient for this character type; box-proxy request declined on technical grounds (character has no bending joints)
- Studio CPO concluded: adapting production asset standards to junior skill gaps is the wrong direction; the standard should be set by the pipeline's needs, not the team's current capability ceiling
- Studio CPO observed: box-proxy escalation via a department head in a leads meeting is an appropriate mechanism but should be assessed technically, not socially -- the public context should not change the technical assessment

## Context

Working session between CPO and senior art lead at a ~60-person UK/Cyprus-based MMO studio, July 2026. The animation team had raised a proxy mesh standard concern. The art lead had already declined in a leads meeting; the CPO confirmed the decision and its reasoning.

## Applicability

Relevant when: an animation team requests simplified proxy meshes citing junior capability -- the correct response is to assess whether the standard proxy is genuinely inadequate for the character type, not to simplify assets to match current skill level.
Relevant when: a character has no bending joints (floating, disconnected, hovering mechanics) -- the standard low-poly proxy is sufficient and box-proxy overhead is not justified.
Relevant when: a junior request is escalated by a department head to a peer in a leads meeting -- assess on technical merit; the public setting should not create social pressure to approve a technically unwarranted request.
Relevant when: a studio is setting production standards during VS -- standards should be set by pipeline requirements and final-product needs, not by current team capability; capability should be built to meet the standard.
