# Systemic Design Philosophy: Resonance, Complex vs Complicated, and Layered Systems

## Key Content

Resonance defined: a gameplay moment that lands, surprises, and is worth retelling to another player. A rough emergent moment that players share beats a flawless scripted moment they do not. Definition of done for systemic features: is it producing resonant moments? Not: does it meet traditional polish standards?

Complex vs complicated distinction:
- Complex: many interacting elements that players can reason through with effort (acceptable, even desirable)
- Complicated: systems with too many inputs for players to infer cause from effect (always bad)
- Test: if a player cannot infer what caused an outcome, the system has too many inputs

Layered systems approach: begin with a small set of simple, readable systems. Add layers incrementally. Do not design all layers upfront.

Day/night cycle as archetype for base layers: one state change (day/night) can be applied to anything sensitive -- animal behaviour, herb spawning, visibility, NPC schedules. This single layer produces emergent content without dedicated feature work. Seasons are a later layer; do not design them at day/night stage.

Player-driven discovery as intended loop: wikis, discovered migration patterns, and shared knowledge (e.g. golden carp example) are part of the gameplay experience, not a failure of tutorial design.

Example of systemic design working correctly: lightning + metal weapon in a goblin camp produces emergent electrocution without a dedicated "stealing mechanic" -- the outcome emerges from reading rules across systems.

## Decisions / Insights

- CPO and Game Director agreed: resonance is the correct definition of done for systemic features -- not polish completeness
- CPO and Game Director agreed: complex is acceptable; complicated is always a design failure -- the test is whether players can infer cause from effect
- CPO and Game Director agreed: day/night cycle is the correct first base layer; seasons are a later addition -- resisted over-designing upfront
- Pattern identified: player-driven discovery (wikis, emergent knowledge sharing) should be designed for, not designed against -- it is part of the gameplay loop in systemic MMOs
- Pattern identified: a single state-change layer (day/night) applied consistently across the game world generates disproportionate emergent content relative to implementation cost

## Context

Two-hour design alignment session between CPO (Glen) and the Game Director of a 55-70 person MMO studio. Focus on systemic design philosophy for an open-world MMO with crafting, exploration, and player-driven economy. Both parties aligned strongly on this philosophy. 2026-07-22.

## Applicability

Relevant when: advising a studio on feature complexity decisions -- the complex/complicated distinction and the "can players infer cause from effect" test are directly deployable evaluation criteria.
Relevant when: a studio is over-designing early game systems (e.g. building seasons before day/night is stable) -- the layered approach with explicit sequencing prevents this.
Relevant when: evaluating whether a game feature is production-ready -- resonance (does it produce moments worth retelling?) is a better gate than polish completeness.
Relevant when: designing a systemic MMO economy or world system -- the electrocution example pattern (emergent outcome from intersecting rules) is the intended design goal.
Relevant when: a client studio is concerned that player wikis and external knowledge-sharing undermine their game design -- reframe as an intended part of the systemic gameplay loop.
