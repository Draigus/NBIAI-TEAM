# Post-VS Phase Structure: Jigsaw Model (MVP / ELP First, Outward)

## Key Content

Framework for structuring the development roadmap after a vertical slice milestone, where features are systemic and interdependent:

**Jigsaw model:** build phases from the center outward. Define the minimum viable player experience (MVP/ELP) first -- the smallest coherent loop that is fun and shippable. Then work outward through themed phases, each adding a layer of systemic depth.

**Why sequencing matters:** systemic features lose value without their neighbours. A crafting system without an economy, or a social system without persistent identity, deliver a fraction of their intended experience in isolation. Phase ordering must respect systemic dependencies.

**Phase mapping approach:** phases map to "yellow boxes" roughed out in a high-level roadmap view. The Head of Design's role (post-VS) is to: audit current feature state, define high-level phases, and build an accurate feature backlog for each phase.

**VS boundary rule:** the post-VS architect (Head of Design) does not get involved in VS execution unless explicitly requested. VS is the Game Director's lead. Additional design input during VS risks being disruptive to the delivery team.

Teams should not spread across too many features simultaneously -- phase structure enforces this constraint.

## Decisions / Insights

- Glen decided: post-VS planning is the Head of Design's primary mandate; VS execution ownership stays with the Game Director
- Glen and Simon agreed: define MVP/ELP first, then work back through themed phases to avoid premature feature sprawl
- Simon observed: systemic features lose most of their value without their neighbours -- sequencing must respect dependencies, not just completeness
- Pattern identified: studios frequently scope post-VS by listing features rather than by defining the smallest coherent player experience first
