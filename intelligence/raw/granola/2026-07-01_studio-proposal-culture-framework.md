# Studio Proposal Culture: Structured Cases, Time-Boxed Evaluation, Preserved Serendipity

## Key Content

A framework for managing unsolicited proposals from studio teams without crushing initiative or creating uncontrolled scope.

**Structured case requirement:**
- Teams submitting proposals must provide: problem, proposed solution, rationale, ask
- The format forces clarity; submitters either back off or become more passionate
- Goal: even rejected proposals should be a learning experience for the team

**Evaluation paths (three options, not binary):**
1. Greenlight
2. Defer to an idea board (not rejected, just not now)
3. Slot into a specific future scope window (e.g. VS2, VS3) with a named milestone

**Time-boxed plugin/tool evaluation:**
- One week maximum to assess any new plugin or system; kill after a week if no demonstrated value
- Extension only week-by-week, conditional on demonstrated value each week
- Pull the tool into an actual build and profile it before any decision -- no paper assessments

**Serendipity preservation:**
- Plans must never be so rigid that unexpected improvements are impossible
- Historical examples: Nemesis system (Shadow of Mordor), multiplayer in GoldenEye, public quests in WoW -- all started as skunkworks ideas
- Advisor's rule: always stop and listen, then decide; the three paths (greenlight / defer / slot) mean every idea gets a destination, not just a verdict

## Decisions / Insights

- Glen decided: all design proposals must use the structured case format (problem/solution/rationale/ask) before receiving any evaluation time.
- Glen concluded: binary accept/reject creates routing behaviour; three-path evaluation (greenlight / idea board / future slot) preserves team passion while maintaining scope control.
- Glen concluded: time-boxing tool evaluation at one week with week-by-week extension prevents open-ended exploration; value must be demonstrated, not assumed.
- Glen observed: plugin proposals (e.g. combat or traversal systems) are rare cases where external tools could save time rather than add scope -- treat differently from feature requests.

## Context

1:1 session between studio advisor (Glen) and the creative director at a ~65-person MMO studio, Jul 1 2026. Two separate plugin pitches (combat and traversal systems) had been raised by designers. The session addressed how to handle unsolicited proposals systematically across a studio generating a high volume of ideas during vertical slice production.

## Applicability

- Relevant when: a studio's scope is expanding through informal proposals and designers feel their ideas disappear -- structured cases + three evaluation paths give ideas a clear destination.
- Relevant when: evaluating a third-party plugin or marketplace tool for a production build -- one-week time-box with real build profiling prevents months of inconclusive exploration.
- Relevant when: advising a studio on handling creative enthusiasm during a constrained production phase -- preserving the "idea board" and visible future slots is as important as the reject mechanism.
- Relevant when: a production leader is concerned about saying no damaging morale -- framing every idea as having a destination (not just a verdict) separates "not now" from "never."
